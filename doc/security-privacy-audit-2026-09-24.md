# HomeBuddy 安全与隐私审计

- 审计日期：2026-09-24
- 审计目标：评估公开 GitHub 仓库及分发应用前的安全、隐私风险。
- 审计基线：提交 `ad1de02`，以及审计时工作区中尚未提交的照片浏览界面改动。
- 审计方式：源码审查、Git 历史扫描、原生静态库字符串检查、隔离运行验证。
- 状态：发现 7 项风险；本次审计没有修复应用代码。

## 结论

在全部 14 个本地可达提交中，未发现已提交的照片、SQLite 数据库或命中本次扫描规则的常见密钥、私钥、口令。这不等于不存在秘密，也不构成完整安全保证。

公开仓库的直接风险主要是已有提交中的开发者身份、本机路径，以及缺少防止后续误提交的忽略规则。应用运行风险主要集中在敏感数据传输、隐式发送人脸向量和删除不完整。

默认 Ollama 和 Chroma 地址均指向本机回环地址。不能仅凭客户端代码认定服务已暴露公网；涉及远端通信的风险需要结合实际配置和服务器部署判断。

## 风险清单

### 1. 高风险（远端部署时）：敏感数据传输缺少约束

**代码位置**：[ChromaService.swift](../HomeBuddy/ChromaService.swift#L266)、[OllamaVisionService.swift](../HomeBuddy/OllamaVisionService.swift#L76)。

两个客户端都允许构造非本机 HTTP 请求，没有应用层的远端 HTTPS 强制规则，也没有认证凭证配置或认证请求头。Ollama 接收照片；Chroma 接收人脸向量，写入记录还包含姓名、人物 ID 和照片标识。

当配置为远端 HTTP 且运行环境允许该请求时，敏感数据可能被窃听或篡改。服务端是否允许未经授权的读写取决于其部署，不能仅根据客户端没有认证头就认定服务端存在未授权访问漏洞。

**建议**：只对明确的回环地址允许 HTTP；远端强制 HTTPS，校验协议、主机及重定向目标。支持服务端认证，将认证秘密保存到 Keychain。部署说明应要求限制监听地址、网络访问范围和数据库权限。

**验证**：使用真实服务源码和 URLProtocol 拦截，两个客户端均成功构造非回环 HTTP POST，且没有 Authorization 请求头。只使用合成数据，没有实际网络传输；该验证不代表真实环境中的 ATS、TLS 或服务端认证检查已通过。

### 2. 中风险：取消人物关联可能留下远端生物特征

**代码位置**：[PhotoLibraryView.swift](../HomeBuddy/PhotoLibraryView.swift#L678)。

取消人物关联先更新本地 SQLite，然后才尝试删除 Chroma 记录。若回调时已切换照片，或者内存中没有匹配的 embedding，远端删除会被跳过。网络失败时虽然可能显示错误，但没有持久化的删除重试任务。

结果是本地看起来已经取消关联，Chroma 中却可能继续保留人脸向量、姓名和照片标识。以后重新识别该照片可能清理索引，但不能保证一定发生。

**建议**：删除应只依赖持久化记录标识，不依赖当前界面或重新计算 embedding。保存待删除任务并重试，明确显示未同步状态；补充切换照片、模型不可用及 Chroma 离线场景的测试。

### 3. 中风险：浏览照片会隐式发送人脸向量

**代码位置**：[自动启动识别](../HomeBuddy/PhotoLibraryView.swift#L725)、[向量查询](../HomeBuddy/PhotoLibraryView.swift#L817)。

配置模型后，仅打开大图即可自动触发识别，并将未标注人脸的向量发往配置的 Chroma 服务用于查询。已确认人物还可能被自动写入索引。

因此，实际数据流不只是“保存已确认人物”，也不一定局限于本机。查询并不意味着客户端将未标注向量持久写入 collection，但服务端已经收到该生物特征，其日志和保留策略未验证。

**建议**：默认关闭自动发送；首次启用和更换服务器时，明确说明接收方及发送的数据类别并取得确认。提供仅本地检测的模式，避免把模型已配置等同于用户同意向服务端发送数据。

### 4. 中风险：转换失败时上传原始照片

**代码位置**：[BatchRecognitionView.swift](../HomeBuddy/BatchRecognitionView.swift#L187)。

批量识图使用 `jpegData(from: data) ?? data`。JPEG 转换失败时，会直接采用 Photos 返回的原始数据，绕过缩小和重新编码路径，可能将 GPS、拍摄时间等 EXIF 信息一并发送，也可能发送远大于预期的文件。

**建议**：转换失败时终止该张照片的上传并报告错误，不回退到原始文件。统一单张和批量上传的数据净化策略，加入输出大小、格式及元数据检查。

**验证边界**：已确认源码中的回退路径；没有使用真实照片复现转换失败或检查其 EXIF。

### 5. 中风险：敏感缓存长期保留，缺少完整清除能力

**代码位置**：[SQLite 创建](../HomeBuddy/PhotoLibraryStore.swift#L503)、[数据库复制](../HomeBuddy/PhotoLibraryStore.swift#L256)。

普通 SQLite 数据库保存识别文字、姓名、人物与照片关联等信息，没有应用层加密。切换存储目录只复制数据库，旧副本仍然存在。未发现完整清除入口，也未发现照片从图库删除后同步清理本地及 Chroma 数据的处理。

拥有数据库文件读取权限的程序、备份接收方或共享目录使用者可能读取这些信息。应用沙盒和操作系统保护仍然有效，不能据此认定任意用户都能读取数据库；实际文件权限、FileVault 和备份策略未检查。

注意：当前 `location` 字段只记录是否包含 GPS 信息，不保存实际坐标。识别文字本身仍可能包含照片中的敏感内容。

**建议**：提供清除识别文字、人物记录及远端向量的能力，并处理照片删除后的数据生命周期。迁移后明确提示旧副本存在，允许用户确认清理。限制目录和文件权限，对共享目录或同步目录给出提示，并根据威胁模型评估数据库加密。

### 6. 中风险：异常服务端距离可导致崩溃

**代码位置**：[距离校验](../HomeBuddy/PhotoLibraryView.swift#L832)、[百分比转换](../HomeBuddy/FaceRecognitionService.swift#L16)。

候选距离只检查有限性和上界，没有合理下界。恶意或异常服务端返回极大负数时，只要候选的其他字段满足条件，该距离就能通过检查；随后相似度百分比转换为 `Int` 会因超出范围而触发运行时错误。

**建议**：按所使用的 cosine distance 语义校验合理范围，必要时处理小幅浮点误差；百分比转换前检查可表示性并限制展示范围。增加异常负数、超大数及边界值测试。

**验证**：使用 `-1e300` 验证其可通过现有距离条件，但计算出的百分比不能表示为 `Int`。没有实际触发应用崩溃，也没有连接真实服务端。

### 7. 低风险：公开开发者身份和本机路径

**证据位置**：[原生静态库目录](../HomeBuddy/Native/lib)、[项目配置](../HomeBuddy.xcodeproj/project.pbxproj#L307)、[Xcode 用户配置](../HomeBuddy.xcodeproj/xcuserdata/twinsant.xcuserdatad/xcschemes/xcschememanagement.plist)。

静态库字符串包含构建机器的用户名和源码绝对路径；Git 提交历史包含个人邮箱；项目还提交了 Xcode 用户配置和签名 Team ID。这些不是登录凭证，但会形成可公开关联的身份信息。

本报告不再复制完整个人邮箱和构建路径，以免新增一份需要清理的记录。

**建议**：先确认是否愿意公开这些信息。不需要的用户配置应停止跟踪；原生库可通过路径映射重新构建以去掉个人路径，不能假设只剥离调试符号就能移除所有路径字符串。若要求历史中也不再出现，需要另行评估历史重写或建立干净发布历史；仅新增删除提交不能清除旧版本。本次没有修改 Git 历史。

## 发布前建议

### 公开源码前

- 确认并处理不愿公开的提交身份、本机路径和 Xcode 用户配置。
- 增加忽略规则，防止后续误提交 SQLite 数据库及其 journal/WAL 文件、模型权重、构建产物、凭证和用户配置。忽略规则不会移除已经跟踪的文件。
- 原生依赖目前主要以静态库提供，建议补充来源、固定版本或提交号、校验值及构建步骤，便于审计和更新。
- 补充隐私说明，准确描述本地缓存、Ollama 照片处理、Chroma 向量传输及删除方式。
- 明确项目自身许可证，并核对依赖及模型权重的授权范围。已有第三方许可证文件不自动决定整个项目的许可；当前界面也提示模型权重存在非商业使用限制。

### 分发应用前

- 优先修复远端传输约束、删除不完整和隐式发送问题。
- 移除原图上传回退，增加异常服务端响应防护。
- 提供清除和迁移残留管理，并补齐对应的行为测试。
- 在实际 macOS 应用环境验证 HTTPS、重定向、认证、离线删除恢复以及用户授权流程。
